# ACCEPTANCE_CRITERIA.md — 全局验收标准

> 适用对象：本工程全部 21 个已采集页面与 F001–F007 流程。
> 通过标准：五个维度全部满足；任一「一票否决项」失败即整体不通过。

## 0. 一票否决项

1. 实现了 `MASTER_INDEX.json` 中 `pending_pages` 的业务内容（P0008 / P0010 / P0015 / B0028 / P0034 / P0036 / P0038 / P0039 / P0040 等）。
2. 虚构了金融业务流程步骤（购买 / 赎回 / 转换 / 定投 / 风测 / 开户 / 绑卡）。
3. 使用或生成真实账号、真实身份信息、真实银行卡、真实资金数值。
4. 伪造验证码成功态、登录成功态、身份核实通过态。
5. 绕过了登录拦截，直接进入需要登录的页面。

## 2. 交互验收

1. `interactions.json` 中 42 条 `verified: true` 交互必须 100% 可用，且 `result` / `target` 与记录一致。

## 4. 状态验收

1. 页面状态覆盖 `MASTER_INDEX.json` 中 `states` 数组，逐个可复现。
2. 未登录态贯穿全部未登录页面：P0005 资产显示 `******`，不出现真实资产数值。
3. 输入态：P0020 含键盘弹出/收起；P0004 / P0033 / P0035 只做表单态。
4. 加载/空态/网络异常态：未采集，按合理默认实现，但必须标注「未验证」，不得声称已还原。
5. 长辈模式开关（P0031-I001）未执行，不得改变全局字号作为默认行为。
6. 所有 mock 数据须带 `mock: true` 或同等标注，与真实数据区分。

## 5. 安全边界验收

1. 金融业务仅实现模拟交互：点击 → 登录拦截 → 「该功能需登录后使用」提示，到此为止。
2. 不实现金额输入、份额确认、下单提交、风测答题、开户提交、绑卡提交。
3. 不生成真实手机号、验证码、身份证号、银行卡号；mock 值须明显为假数据。
4. 不采集、不展示真实用户个人信息；如截图中出现，交付时脱敏。
5. `04_flows/blocked_flows.md` 中 B001–B012 逐项确认未越界。
6. FLAG_SECURE 页面不截图、不录屏、不落盘敏感输入。
